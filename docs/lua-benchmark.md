# Lua 实体压测

运行 `lua tools/benchmark.lua [帧数] [种子]`。默认是 Lua 5.3、固定 60 Hz、360 帧（6 秒模拟时间）、种子 21713、48 单位分桶。100/300/600 个实例按敌人 60%、投射物 25%、拾取物 15% 分配，玩家位置由固定轨迹提供。敌人追踪玩家，投射物用扫掠圆碰撞，范围内的拾取物向玩家移动。各模式使用相同的定时回收与重生序列，实体总数固定。

每帧记录进程 CPU 耗时，分列移动和碰撞均值及总帧时的 p50、p95 和最大值。候选数是进入精确扫掠检查的实体对数。`mem_peak` 是帧后采样峰值，`mem_gc` 是末尾强制 GC 后的留存量，两者均相对运行前完成设置并执行 GC 时的基线。`new` 只计算替换实体时创建的表。对象池模式按槽位重置实体表，分桶模式复用分桶存储。压力场景只计接触事件，战斗伤害、穿透和回收规则由 Lua 核心回归测试单独验证。

## 默认参数实测

本地 Debian x86_64、Lua 5.3.6 的一轮结果。候选检查数和碰撞指纹固定，CPU 和内存受运行环境及 GC 影响。

| 实体 | 策略 | p50 / p95 / 最大值（毫秒） | 候选检查 | 命中 | 内存峰值增量（KiB） |
| --- | --- | ---: | ---: | ---: | ---: |
| 100 | 线性、重新分配 | 0.366 / 0.542 / 1.316 | 540000 | 1060 | 205.1 |
| 100 | 分桶、对象池 | 0.062 / 0.083 / 0.132 | 14373 | 1060 | 25.2 |
| 300 | 线性、重新分配 | 3.290 / 4.320 / 7.047 | 4860000 | 9935 | 532.9 |
| 300 | 分桶、对象池 | 0.236 / 0.307 / 0.399 | 130378 | 9935 | 46.8 |
| 600 | 线性、重新分配 | 13.226 / 15.748 / 29.201 | 19440000 | 40091 | 875.3 |
| 600 | 分桶、重新分配 | 0.703 / 1.764 / 7.248 | 545384 | 40091 | 1008.4 |
| 600 | 分桶、对象池 | 0.679 / 0.976 / 10.297 | 545384 | 40091 | 77.9 |

全频率分桶加对象池与线性扫描的每帧接触计数和指纹一致，程序出现差异时退出失败。600 实体下分桶重新分配和对象池各更新 3734 个实例，对象池复用原表。分桶、对象池在这一轮把 600 实体的保留增量控制在 76.6 KiB。

错开投射物碰撞每隔一帧检一次，三档分别减少 519、4910、19787 次接触。将敌人移动减为 30 Hz 时，三档接触总数分别变化 0、−43、+26，接触不同的帧数分别是 76、308、357。100 实体下总数相同也存在碰撞差异。

TS-11 的千星对照参数为相同种子、三档组成、回收周期、连续 6 秒、48 单位分桶和 60 Hz 逻辑。先比较线性基线与全频率分桶加对象池，实机另外测脚本帧时、渲染帧时、活跃控件和低帧情况下的输入表现。上述 Lua CPU 结果仅对应无界面合成场景。
